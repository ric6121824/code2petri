# 08 — JavaScript Walker Skeleton & Basic Statements

**What to build:** The first operational vertical slice of JavaScript support. The CLI can now accept a `.js` file, parse it using the Acorn engine under the hood, and output a valid Petri net for global-scope code and basic sequential statements (like assignments and function calls). Transition labels accurately reflect the JavaScript source code.

**Blocked by:** 07 — Prefactor: Walker Protocol & Shared Infrastructure

**Status:** ready-for-agent

- [x] `JavascriptWalker` class is implemented, inheriting from the ABC and `_BaseControlFlowWalker`.
- [x] `engine.py` correctly routes `.js` files to `JavascriptWalker`.
- [x] `parse_file` delegates to `code2flow`'s `Javascript.get_tree()`, automatically supplying the required `LanguageParams(source_type="script")` configuration and caching the raw source text.
- [x] `find_function` supports a synthetic `(global)` wrapper for top-level code.
- [x] Transition labels are generated by slicing the raw JS source using Acorn's `start` and `end` offsets.
- [x] `walk_function` correctly handles sequential statements, `return` statements, and opaque function calls.
- [x] A new `test_javascript_walker.py` verifies these features against small JS test fixtures.
