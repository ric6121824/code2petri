# 60: Inspect called functions through folding and restoration

**What to build:** Users can inspect return metadata on an unambiguously resolved Call Site before Inline Expansion and on the resulting function compound in expanded or Collapsed Compound State. Correct function identity and available evidence survive repeated calls, renaming, nested folding, saved-session restoration, and Component-Local Unfold without making session history grow through duplicated metadata.

**Blocked by:** [55 — Inspect JavaScript Function Return Metadata](./55-javascript-function-return-metadata.md).

**Status:** resolved

- [x] Associate a resolved Call Site with the exact callee function record using source file and definition identity, including qualified name/location where needed. Repeated calls may share the record; bare method names, node/container IDs, display labels, and compact expression-and-type text are insufficient identities.
- [x] Root, callee nets, cloned/composite nets, serialized compounds, and viewer elements intentionally retain the associations through precomputation and Inline Expansion. Caller-owned or removed callee boundary places must not determine metadata ownership.
- [x] The docked sidebar shows available function identity, declared/documented evidence, inferred type/state, known partial observations, role labels, and source expression evidence for resolved call transitions before expansion and expanded/collapsed function compounds afterward. Reuse the shared presentation so subsequent Tickets 56–59 automatically extend the same inspection behavior; their richer extraction is not a blocker for the ordinary-function cases delivered here.
- [x] Sidebar evidence uses explicit fields such as Returned expression, Inferred type at this return, and Evidence. Compact x: int (inferred) or x: unknown (inference unavailable) is optional explanatory display text. Store and restore expression, type, state, provenance, role, and source location separately; never rename x or parse the label on a colon.
- [x] An inferred expression type is scoped to its source return/yield site rather than a permanent type of that name. The lowercase unknown analysis status remains distinct from a written source type named unknown. Source expressions containing object/conditional colons remain intact, and text is not interpreted as HTML.
- [x] Same-named functions in different files, qualified/nested definitions, and multiple call occurrences do not borrow another function's record. Ambiguous/unresolved calls show unknown without guessing or expanding the existing constructor-only resolution scope.
- [x] Structural Folding does not recompute, merge, or fabricate function return contracts. Function compounds retain their identity through Collapsed Compound State and Component Node Renaming. An arbitrary component spanning several functions receives no invented single contract or new constituent-function list.
- [x] Component-Local Unfold restores function associations and earlier nested components exactly while preserving unrelated folds. Metadata inspection does not consume graph nodes or alter existing place triggers, Batch Place Fold, Fold-Entire-Function, layout, selection controls, or viewport behavior.
- [x] Save/open preserves the function registry/references, root and callee context, recursive restoration records, role evidence, remembered names, configuration, fold history/counters, weights/SM, layout, and viewport without source access or inference. Opening another root and reset/playback describe the active session. Metadata is retained in generated HTML and public net JSON; PNML/DOT behavior remains unchanged.
- [x] Old valid version-1 snapshots without metadata remain readable. Validate recognized records and associations, including restorable nested contexts, before replacing active state; malformed metadata leaves the current graph/context intact. Do not reconstruct missing evidence from a label.
- [x] Keep a function record with lightweight references wherever possible. Snapshot capture remains detached and preserves compact canonical history; do not copy full ASTs/source files or duplicate the registry at each restoration level. Repeated calls and nested folds must not recursively multiply complete records.
- [x] Extend the production source-to-viewer/save-open-continue-unfold workflow with ordinary Python/JavaScript declared/literal examples supported by Tickets 54–55, repeated calls, same-named definitions, unambiguous and unresolved calls, expansion, collapse, rename, nested unfolding, root replacement, and malformed associations. Assert correct sidebar evidence and separately persisted fields rather than internal adapter names or display-string parsing.
- [x] Extend the existing 12-level nested-fold fixture with representative function records/references, retain its below-100-KiB snapshot bound, and reopen/unfold every level losslessly. Compare graph identities/endpoints, markings, fold eligibility/results, Transition Weight, Component Penalty, and Structuredness Metric with metadata absent/present. Automated fixtures remain self-contained, with no user-specific source paths or timing thresholds.
- [x] The basic called-function slice can start after Ticket 55 and run alongside Tickets 56–59. Use functions foldable under the current engine; Ticket 53's shared-boundary folding fix is independent and must not become an implicit prerequisite or part of this ticket.
