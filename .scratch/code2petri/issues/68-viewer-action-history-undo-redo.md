# 68: Viewer Action History — Undo and Redo

**What to build:** Let users undo and redo committed graph edits in the current open viewer, with one entry per gesture. Restore each gesture's exact graph result while preserving the user's current camera, viewing preferences, and existing Component-Local Unfold capability.

**Blocked by:** None (can start immediately).

**Status:** ready-for-human

- [x] Cover individual elementary/structural folds, Batch Place Fold, Fold-Entire-Function, Component-Local Unfold, committed renames, completed node moves, Reset, precomputed fold-step changes, and function-call expansion/collapse. Save/export, search typing/highlighting, selection, inspection, sidebar visibility, pan, and zoom do not add entries.
- [x] Record one gesture as one entry, including every internal reduction in a batch/function fold and every moved descendant or selected node in a completed compound/group drag. Expose the same boundary for Ticket 69 to group its entire multi-level Reveal. Uncommitted typing and unchanged/cancelled drags create no entry.
- [x] Undo restores the prior graph/editing state; Redo restores the exact recorded result rather than rerunning detection. Preserve topology, tokens, parents, collapsed state, nested local-unfold records, names/remembered names, positions, weights/SM, metadata associations, component-ID allocation, and relevant playback/expansion state. Continued editing must remain valid without component-ID collisions.
- [x] Keep the user's current zoom and pan during Undo/Redo. Retain current sidebar visibility and current search query; refresh live controls/results instead of restoring historical search highlights, selection, or camera movement.
- [x] A successful new edit after Undo clears Redo. Failed and unchanged actions create no entry and preserve Redo. A valid partial-progress batch/function action is one undoable entry; an operation that errors rolls back its changes and history position.
- [x] Failed Undo/Redo leaves the pre-attempt graph, metadata, current view, and history cursor/stacks intact. Do not trust a partially successful restoration or silently missing nodes/edges as a completed action.
- [x] Put Undo/Redo buttons beside search in the top toolbar and disable them when unavailable. Provide Cmd/Ctrl+Z, Cmd/Ctrl+Shift+Z, and Ctrl+Y where appropriate, while preserving native undo/editing in inputs, textareas, editable content, and active text composition. Explicit toolbar buttons still operate on graph history.
- [x] Preserve unfinished naming text when the same inspected node survives; refresh committed node metadata separately. If its node disappears, clear inspection and its draft using existing behavior. Retain surviving current selection IDs and remove invalid ones without replaying an old selection or forcing the sidebar open.
- [x] Keep history in the current open viewer only. Save Session retains the current graph and canonical nested local-unfold records without Undo/Redo stacks or a new schema. Saving/exporting does not clear history. A successful Open Session starts empty history; an invalid/rejected open preserves the graph and history. History restoration itself must not act like incoming-session replacement.
- [x] Retain at most 50 gestures across Undo and Redo together, with a soft approximate 32 MiB serialized-history-data budget. Evict oldest entries without breaking the remaining history path; always keep the newest action undoable even if it alone exceeds the soft byte budget. Do not present this as a hard heap-memory guarantee.
- [x] Keep restoration capture compact and detached, avoiding recursive duplication of legacy aliases, document/playback payloads, or full metadata catalogs across history entries. Eviction and branch clearing release unreachable records; later live edits cannot mutate retained before/after states.
- [x] Verify through production generated-viewer actions with real bundled Cytoscape: every approved mutation route, whole-gesture grouping, exact Undo/Redo, remembered names after unfold/refold, compound/group moves, playback/expansion controls, continued component allocation, partial progress, branching, no-ops, injected failures, retention eviction, and current-camera preservation.
- [x] Exercise production save/open with nested history and metadata: files contain the current graph without action stacks, remain compact and compatible, reopen with empty action history, and continue ordinary folding/local unfolding. Rejected Open and failed history restoration leave current state intact.
- [ ] Check actual generated-HTML browser behavior for toolbar placement, disabled state, pointer drag grouping, focus, native text shortcuts, surviving drafts, hidden-sidebar preferences, and zoom/pan. Report missing browser acceptance as a gap; mocked DOM or source-pattern checks alone do not establish those behaviors.

## Context and decisions

This is a Phase 2.8.1 implementation ticket, extracted from the Phase 2.8 follow-up scope. It complements the existing local restoration contract rather than replacing it with chronological playback. The current engine's unused history field is not an implementation of this feature. Internal history representation and module factoring are implementation choices; one production action boundary must cover every approved route and be reusable by Reveal.

The retained two-ticket plan separates a complete Undo/Redo feature from [Ticket 69 — Node Search and Explicit Reveal](./69-node-search-and-explicit-reveal.md). Ticket 69 depends on this boundary because the user requires one Undo for an entire Reveal and rollback for failed multi-level restoration. Existing delivered tickets are not reopened.
