# 69: Node Search and Explicit Reveal

**What to build:** Let users find named node occurrences through a top-toolbar search, including nodes retained inside nested Folded Components. Locate results without changing the graph, then explicitly Reveal a hidden occurrence through normal unfolding, with the entire Reveal forming one Undo/Redo action.

**Blocked by:** [68 — Viewer Action History — Undo and Redo](./68-viewer-action-history-undo-redo.md).

**Status:** ready-for-human

- [x] Search the current graph and all its restorable hidden nodes, including nested restoration records. Do not add unused source definitions, other playback states, original-net backups, or unexpanded callee-template copies as extra current occurrences. Search must work offline without source execution or access.
- [x] Match literal case-insensitive substrings across node labels, stored original function names, custom names, and node IDs. Do not invent overwritten labels or infer identity from the query. Include places, transitions, and function compounds where their current/restorable records exist.
- [x] List repeated occurrences separately with caller path, unique occurrence ID, and source location where available. Track exact occurrence/restoration ownership separately from function ancestry; a shared callee-definition reference or a stale node object is insufficient. Avoid counting canonical/legacy restoration aliases twice.
- [x] Put the search bar and results dropdown in the top toolbar, usable with the right sidebar hidden. Use an X clear control inside the field's right edge, shown only when the query is nonempty. Distinguish visible/hidden results and provide readable occurrence context and empty/no-match feedback. Bound rendered work without silently discarding additional matches; preserve access to all results.
- [x] Choosing a result or pressing Enter performs Locate only: highlight the visible target or its currently visible containing component, preserve zoom, and center it. Use dedicated navigation rather than synthesizing a node tap, fold, unfold, or source-call expansion.
- [x] Keep search highlights separate from graph selection and inspector contents. Locate/search typing must not replace batch selections, change inspection, discard/commit naming drafts, or force a hidden sidebar open. Clearing search removes its query/highlights without refolding or clearing graph selection.
- [x] Up/Down navigates results; Enter locates the active result; Escape closes the dropdown while retaining the query. Keep Reveal an explicit action with an accessible control. Preserve native text editing and composition, including the input's own Undo/Redo.
- [x] A hidden result offers Reveal when its actual retained interior can be restored. Locate an opaque-child ID already represented by a collapsed compound through that visible tile; do not offer an unfold that destroys the matched component merely to claim it was revealed.
- [x] Reveal restores only the containing folds needed to reach the exact occurrence. Each opened component may restore its full immediate interior, including neighboring nodes; off-path folded components remain folded unless needed for the target. After each required owner unfolds, use the same whole-graph layout as right-click Component-local Unfold without fitting the camera. Unrelated node positions may change; keep zoom and center the revealed target.
- [x] Treat Reveal as ordinary persistent graph unfolding: update weights/SM normally, retain the unfolded result when the query changes/clears, and save that current graph through existing Save Session. Do not introduce an automatic refolding preview mode.
- [x] Use Ticket 68's action boundary so an entire multi-level Reveal is one history entry. One Undo returns the pre-Reveal folds; one Redo restores the exact graph result and same occurrence. Undo/Redo keeps the user's current zoom/pan rather than replaying the original Reveal navigation.
- [x] Revalidate the exact target and its current restoration chain before mutation and after each unfold. Require a visibly represented target on success. Missing/stale/unrestorable matches produce useful feedback without guessing from source or historical copies. An error rolls back the whole Reveal, attempted navigation/UI changes, and history position; no partial failed Reveal or empty history entry remains.
- [x] Preserve the query and refresh/reconcile results after edits, renaming, Reset, playback/expansion changes, Undo, and Redo. Keep result identity stable where the occurrence survives; do not jump to a different same-named call when one disappears. Successful Open Session clears query/results; rejected Open leaves current search and graph intact.
- [x] Reuse the existing generated-viewer and production snapshot seams with self-contained nested/repeated-call fixtures. Cover hidden places/transitions/compounds, visible and deeply hidden matches, literal special characters, case variants, aliases/custom names, duplicate names and legacy restoration aliases, current-state-only scope, collapsed-tile representatives, live refresh, and missing/stale records.
- [x] Verify Locate is graph-neutral and Reveal preserves unrelated topology/positions, names, tokens, metadata, correct weights/SM, and hierarchy. Cover one-entry Undo/Redo, failure injected after intermediate restores, existing local unfolding, save/open of the revealed graph, empty history/query on successful Open, and malformed-session preservation.
- [ ] Use actual generated-HTML browser acceptance for toolbar/dropdown layout, labels and context, Up/Down/Enter/Escape, explicit Reveal, target centering at unchanged zoom, independent selection/inspection/highlights, same-node draft continuity, and hidden-sidebar access. Do not substitute mocked DOM or CSS strings for rendered/pointer/focus behavior; record unavailable coverage honestly.

## Context and decisions

This is a Phase 2.8.1 implementation ticket, extracted from the agreed Phase 2.8 follow-up scope. Folded interiors already retain the node and arc data required for local restoration, so search can discover those occurrences without unfolding them. Restoration ownership is distinct from compound parentage: folds may cross container boundaries, and several call occurrences may share a function definition.

Reveal follows the existing Component-local Unfold action for each owner on the exact target path, including its full-graph layout after each step, while grouping the sequence into one history entry. No new reduction rule, source resolution, inline-depth expansion, saved search history, or session schema is introduced.
