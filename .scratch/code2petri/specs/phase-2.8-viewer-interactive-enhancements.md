# Phase 2.8: Viewer Interactive Enhancements

Status: ready-for-agent

The original Tickets 45–50 are resolved. Ticket 63 adds the agreed Project Title follow-up; Ticket 64 adds optional Docked Sidebar visibility to the existing viewer and session workflow.

## Problem Statement

The HTML Petri net viewer lacks fluid interaction models for bulk reduction and session continuity. The current floating inspector popup obscures the canvas and is disconnected from the node it describes. Reducing a heavily nested function requires clicking every place node inside it one by one, which is tedious. Furthermore, closing the browser throws away all Live Fold reductions and camera panning done during a session; there is no way to save the interactive state to pick it up later.

The delivered info panel identifies the source file and root function but does not identify the source project. A Tic Tac Toe Global Scope view can show main.py and Global Scope without showing Tic Tac Toe. Source subdirectories, normalized output filenames, and dated output folders do not reliably supply the human-readable project name. Users need project identity to remain correct when comparing function views and analysis runs or opening a saved session inside another project's viewer.

The delivered Docked Sidebar always occupies graph space, even when the user wants to concentrate on the graph. Its existing clear-inspection control clears node details but does not hide the sidebar. Users need to reclaim its width and explicitly recall the inspector without losing their camera position, node inspection, or unfinished naming text.

## Solution

We will upgrade the viewer UI from a floating inspector popover to a docked right sidebar (Variant A) that pushes the canvas horizontally, providing a permanent home for metadata and bulk action buttons. Cytoscape box selection will be enabled, allowing users to drag-select multiple places and trigger a single-pass "Batch Place Fold". For compounds, a new "Fold Entire Function" button in the sidebar will recursively fold eligible descendant places until the compound collapses or no further progress is possible. Finally, the bottom-left info panel will surface the active `function_name` alongside the source file path.

The existing generated HTML remains the self-contained viewer, with its graph and feature code embedded. "Save Session" downloads a JSON Fold State Snapshot containing session data, including the subgraphs needed for later unfolding, without another copy of the viewer code. To resume, the user opens a generated HTML viewer with these features and uses "Open Session..." to load the snapshot. This phase retains the current offline HTML architecture; a standalone application and PNML import are deferred.

Add Project Title as explicit generation metadata. The CLI and programmatic generation API accept an optional title, and batch generation supplies each game's human-readable name before filename normalization. Display Project, File, and Function in that order in the existing info panel. All Global Scope and named-function viewers for a project, including dated and fixed outputs, share its title. Save/open retains and replaces the title with the active session's identity. Missing titles display Project: Unavailable; opening an older session clears any title belonging to the host viewer. Titles are supplied during generation, with no viewer editing control in this follow-up.

Add a small hide/recall edge tab near the top of the sidebar's left boundary. Hiding removes the entire sidebar and returns its width to the graph; the tab remains near the top of the graph's far-right edge for recall. Showing restores the existing docked width. Use a right-pointing chevron to hide and a left-pointing chevron to recall, with no animation. Selection and inspection continue while hidden without automatically showing the sidebar. Visibility is distinct from clearing inspection and is preserved in saved sessions. New viewers and older snapshots default to shown; Reset retains the current visibility choice.

## User Stories

1. As a user, I want the node inspector to live in a docked sidebar that pushes the canvas aside, so that my view of the graph is never obscured by a floating popover.
2. As a user, I want the sidebar to maintain the production light theme, so that the viewer remains visually cohesive.
3. As a user, I want to drag a selection rectangle around multiple place nodes, so that I can select them at once using standard box selection.
4. As a user, I want to click a "Fold Selected Places" button in the sidebar when multiple places are selected, so that I can trigger a Batch Place Fold that sequentially evaluates and folds all contractible places in the selection in one pass.
5. As a user, I want to select a compound node and click a "Fold Entire Function" button in the sidebar, so that the engine recursively folds eligible places within that compound until it reaches a Collapsed Compound State or no further progress is possible.
6. As a user, I want to click a "Save Session" button in the toolbar, so that I can download a Fold State Snapshot (`.json`) containing the current net, fold state, component names, node layout, and camera viewport.
7. As a user, I want to click "Open Session..." in the generated HTML viewer and select a previously saved Fold State Snapshot, so that I can resume the same visual state and continue folding, renaming, and locally unfolding components, including components folded before saving.
8. As a user, I want the bottom-left info panel to display the source `function_name` next to the file name, so that I can immediately identify the root function of the displayed Petri net.
9. As a user, I want the info panel to display the Project Title, so that I can distinguish games whose entry files have the same name.
10. As a user, I want to supply a Project Title through the CLI, so that one-off generated viewers identify the source project accurately.
11. As a user, I want to supply the same title through the generation API, so that scripted exports carry project identity consistently.
12. As a user, I want batch generation to use the human-readable game name, so that Tic Tac Toe and Dots & Boxes retain their intended wording.
13. As a user, I want Global Scope and individual function viewers to share the Project Title, so that I can relate separate views of the same project.
14. As a user, I want dated and fixed outputs to retain the same title, so that an analysis-run suffix does not change project identity.
15. As a user, I want Project, File, and Function displayed in that order, so that the panel identifies the project before its source file and root function.
16. As a user, I want long titles and titles containing special characters to remain readable as text, so that the panel stays usable without changing my title's meaning.
17. As a user, I want a missing title shown as Unavailable, so that guessed folder names or undefined values do not misidentify the project.
18. As a user, I want Save Session to preserve the Project Title, so that I can resume offline with the same identity.
19. As a user, I want Open Session to replace the host viewer's Project Title, so that the panel describes the graph I actually opened.
20. As a user, I want an older session with no title to clear the host title, so that unrelated project identity cannot remain on the panel.
21. As a user, I want reset, playback, and function inspection to retain the active project's identity, so that using existing viewer controls does not revert the title to another document.
22. As a user, I want invalid title metadata rejected before session replacement, so that a malformed snapshot cannot damage the active session.
23. As a user, I want to hide the entire Docked Sidebar, so that its width becomes available for inspecting the graph.
24. As a user, I want a recall tab to remain near the top of the graph's right edge, so that hiding the sidebar never removes my way to show it again.
25. As a user, I want the tab on the sidebar's left edge when shown, so that its position communicates the panel it controls.
26. As a user, I want instant visibility changes without animation, so that hiding and recalling feels direct.
27. As a user, I want hide/recall to preserve graph layout and zoom/pan, so that I do not lose my place in the graph.
28. As a user, I want node inspection to update while the sidebar stays hidden, so that recalling it shows current details without overriding my visibility choice.
29. As a user, I want clear inspection to remain a separate action, so that hiding does not discard the node I am inspecting.
30. As a user, I want unfinished naming text preserved when I hide and recall the same node, so that making graph space does not discard my edit or silently commit it.
31. As a user, I want saved sessions to retain sidebar visibility, so that resuming also restores my viewing arrangement.
32. As a user, I want older sessions and new viewers to start with the sidebar shown, so that existing inspector access remains familiar.
33. As a user, I want Reset to preserve my current sidebar visibility, so that resetting graph state does not override my viewing preference.
34. As a keyboard user, I want a labeled and focusable edge tab in both states, so that I can hide and recall the sidebar without a pointer.
35. As a user, I want invalid visibility metadata rejected before changing the session, so that malformed input cannot change my active graph or UI state.

## Implementation Decisions

- **Variant A Docked Sidebar:** We will remove the absolute-positioned `#inspector-panel` from `template.html` and replace it with a flex-based `<aside>` sidebar on the right. The `#main-container` will become a flex row containing `#cy` (with `flex: 1`) and the sidebar (fixed width). The sidebar will inherit the light theme colors from the existing production styles.
- **Optional Docked Sidebar visibility:** Ticket 64 refines the original permanently-visible policy under the amended docked-sidebar decision. When shown, retain the existing fixed-width flex sidebar without overlaying the graph. When hidden, remove the whole sidebar from layout and return its full width to the graph; only the small recall tab remains at the edge. The change is immediate, with no slide, fade, or width animation. Keep sidebar visibility as a distinct state from node selection, inspected-node identity, empty/content state, and the existing clear-inspection action.
- **Edge-tab placement and accessibility:** Use one persistent edge-tab button near the top of the graph/sidebar area. With the sidebar shown, attach it to the sidebar's left boundary; with it hidden, anchor it to the graph's far-right edge at the same near-top position. The tab must not disappear with hidden panel contents, scroll out of reach with inspector content, or be clipped off-screen. Use a right-pointing chevron with Hide Sidebar text/tooltip when shown and a left-pointing chevron with Show Sidebar text/tooltip when hidden. Provide keyboard activation, visible focus, and an accessible name/state. When hiding would leave keyboard focus inside invisible contents, move focus to the tab. Hidden sidebar controls must not remain keyboard-focusable. The edge tab replaces the earlier toolbar-toggle proposal; no duplicate toolbar control is required.
- **Canvas resizing and camera:** After sidebar layout changes, update the graph canvas to its actual available dimensions using the existing viewer/canvas facilities. Preserve node positions, graph structure, zoom, and pan; do not run a graph layout, fit, recenter, reset, or reduction in response to the toggle. The graph canvas retains its existing left/top origin. Recall restores the current sidebar width rather than introducing a resizing interface. Ensure pointer hit testing and graph interaction use the resized canvas correctly.
- **Inspection and drafts while hidden:** Node inspection and selection-driven action availability continue to update without revealing a hidden sidebar. Recall shows the latest valid inspection and Batch Place Fold availability, or the existing empty state if inspection was cleared or its node no longer exists. Hiding/recalling the same node preserves its unsubmitted name text and does not invoke Save Name or clear inspection. Selecting a different node or clearing inspection retains existing replacement/clear semantics; no per-node draft store is added. Existing fold/unfold, programmatic inspector refresh, background taps, and Reset must not force a hidden sidebar to show. Reset keeps the current visibility choice.
- **Visibility persistence and compatibility:** Save Session retains the shown/hidden state as optional viewing metadata in the existing version-1 Fold State Snapshot; exact field naming and placement are implementation choices. Opening a saved session restores its visibility, replacing the host viewer's choice. New generated viewers and old snapshots without visibility metadata default to shown. Validate recognized visibility metadata as a boolean before active-session replacement; malformed additions leave the graph, document, sidebar visibility, and camera intact. Apply the restored sidebar layout and resize the canvas before restoring the saved camera so zoom/pan are not subsequently changed by visibility handling. Preserve detached capture and compact canonical history. This ticket adds visibility persistence only; it does not add persistence for unfinished input text or inspected-node identity, and it does not silently save naming edits.
- **Batch Place Fold (Selection):** We will set `boxSelectionEnabled: true` in the Cytoscape initialization in `template.html`. When the selection contains ≥2 `.place` nodes, the sidebar will show a "⚡ Fold Selected Places" button. Clicking it iterates through the selected places *once* in graph order, executing the appropriate fold on any place that is contractible at the moment of evaluation.
- **Fold-Entire-Function (Compound):** When a `.compound` node is selected, the sidebar will present a "⚡ Fold Entire Function" button. Clicking it triggers an unbounded loop that repeatedly queries all `.place` descendants of the compound for contractibility and folds them until a fixed point is reached (either a fully collapsed state or a state where no remaining places are contractible).
- **Session Serialization:** Use a versioned JSON format for `Fold State Snapshot`, containing:
  - `schemaVersion`: The snapshot format version, validated on open.
  - `elements`: The output of `cy.elements().jsons()`, preserving positions, function hierarchy, component names and weights, collapsed state, and all recursive `consumedSubnet` records needed for Component-Local Unfold.
  - `engine`: The `stepCounter`, folding configuration (`cfg`), and `rememberedCustomNames` serialized as key/value entries. Restore these so continued folding uses unique component IDs, the same penalties, and remembered names after unfold/re-fold.
  - `viewport`: Zoom and pan from the existing `captureViewport(cy)` export in [viewport.js](../../../code2petri/viewer/engine/viewport.js).
  - `document`: Net title, source/function identity, and the originating data needed by existing viewer controls such as Reset or playback. Loading a snapshot must not leave those controls attached to another net's embedded payload.
  - `engine.history` is currently unused. The recursive component records in `elements` provide unfold state; an empty history array is not a substitute for them.
- **Open Session:** A hidden `<input type="file" accept=".json">` triggered by the toolbar "Open Session..." button accepts this snapshot format. Parse and validate the version, graph, and required session state before replacing the active session. Restore graph, engine, document context, and viewport using the existing `restoreViewport(cy, zoom, pan)` export; refresh the inspector, fold affordances, and SM without running a new layout. A rejected snapshot leaves the current session intact. General JSON-net import and PNML import are outside this phase.
- **Info Panel Update:** The data payload parsing in `template.html` will be updated to extract `payload.composite_net.function_name` (or similar) and bind it to a new DOM element in `#info-panel` alongside `#info-filename`.
- **Project Title source:** Extend the existing CLI and generation API with an optional explicit Project Title. Batch generation supplies the original human-readable game name for every game's Global Scope and named-function HTML outputs. Preserve capitalization, spaces, punctuation, and Unicode. Treat omitted or blank titles as unavailable. Do not derive titles from source/output paths, filenames, folder normalization, timestamps, fixed-run suffixes, comments, or another open viewer. This metadata describes the active source project, not a source function or analysis run.
- **Project Title ownership and presentation:** Carry the title in the generated viewer's document context and refresh it with the existing active-document metadata flow. Add a Project row above File and Function, using the existing light-theme info-panel styling and long-name handling. Missing metadata displays Project: Unavailable as a presentation fallback, not an invented project identity. Render titles as text, including characters that resemble markup. Selecting an inlined callee or renaming a component does not change the root document's Project Title. The existing graph/header title has its own meaning and is not repurposed as project identity. Field names and internal factoring are implementation choices.
- **Project Title session continuity:** Include optional title metadata in the current version-1 Fold State Snapshot document context. Save/open is self-contained and requires neither source access nor fresh discovery of a project. Restore the incoming document's title before refreshing the panel; an absent or blank title clears the old identity and displays Unavailable. Recognized title metadata must be a string; malformed additions are rejected through the existing safe-open validation before replacing active graph or document state. Reset and playback use the restored active document. Preserve detached snapshot capture and compact history without duplicating project metadata across nodes or nested restoration records.
- **Project Title actions and containment:** Keep title input at generation time; no viewer editing control is required. Title propagation is document inspection metadata and does not affect Call Site resolution, function identity, graph topology, tokens, fold eligibility/actions, names, weights, Structuredness Metric, viewport, or existing return metadata. No new mathematical reduction or persistence format is introduced.

Open untitled/older sessions to assert Unavailable instead of the host title. Inspect nodes, change selections, clear inspection, edit an unsaved name, and run existing supported graph actions while hidden; assert no implicit recall and current details/action availability on explicit recall. Verify same-node draft preservation without automatic saving and existing replacement semantics for another node. Cover old snapshots defaulting to shown, Reset retaining current visibility, keyboard activation/focus, invalid metadata rejected without mutation, and unaffected graph/document identities, weights/SM, fold history, and compact capture. Reuse the delivered docked-inspector and viewport/session test seams with self-contained fixtures.

## Out of Scope

- Synchronizing fold states back to the Python backend. The Fold State Snapshot is purely for client-side resumption.
- A standalone application, externalizing the embedded viewer code, or changing how the CLI generates self-contained HTML.
- PNML import and general JSON-net import. Open Session reads only saved Fold State Snapshots; existing PNML export remains available.
- Complex error recovery for a corrupted or malformed snapshot; a simple `alert()` or `showToast()` error is sufficient, while preserving the active session.
- Re-theming the entire viewer to a dark mode. The new sidebar must match the existing light theme.
- Automatic Project Title discovery, project-root detection, guessing a title from directory or filename conventions, or per-function/per-node project titles.
- Editing Project Title inside the viewer, project identity propagation into PNML/DOT, or changing the graph/header/browser title or output naming conventions.
- Automatically updating previously generated HTML or enriching old saved sessions from their paths. Regenerate viewers to receive the feature; old snapshots without title metadata remain readable with Unavailable.
- Sidebar animation, floating/overlay inspector modes, drag resizing, a new toolbar toggle, or browser-wide/local-storage visibility preferences. Ticket 64 uses the agreed near-top edge tab and session-specific viewing metadata.
- New persistence for unsaved naming text, inspected-node identity, or per-node drafts, and automatic saving of unfinished edits. Existing selection/inspection replacement behavior remains in force.
